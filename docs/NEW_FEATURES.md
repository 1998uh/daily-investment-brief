# 新功能实现说明

本次实现了 feature-roadmap.md 中的功能 3、4、8。

## 功能 3: Journal 自动生成首稿

### 实现位置
- `pipeline/workstation.py`: `generate_journal_draft()` 函数
- `pipeline/cli.py`: 在 `generate_command()` 中集成

### 功能说明
当使用 LLM 生成日报后，系统会自动读取 `daily-brief.md`，用 LLM 提取核心信息，生成个人判断记录（journal）的首稿。

首稿包含：
- 今日最重要信息
- 改变了什么判断
- 原来的看法
- 现在的看法
- 接下来验证什么
- 错误信号
- 是否调整仓位
- 今日错题或提醒

### 使用方式
```bash
python -m pipeline.cli generate --date 2026-08-22
```

如果是新创建的 journal 且使用了 LLM 生成日报，会自动生成首稿。
输出会显示：`Journal draft (auto-generated): <path>`

### 注意事项
- 只在使用 LLM 模式生成日报时触发（fallback 模式不会生成首稿）
- 如果 journal 文件已存在，不会覆盖
- LLM 调用失败时会静默失败，保留空模板

## 功能 4: 关注标的名单 + 自动标注

### 实现位置
- `config/watchlist.json`: 关注标的配置文件
- `pipeline/generator.py`: `annotate_watchlist()` 函数
- `pipeline/cli.py`: 在 `generate_command()` 中集成

### 功能说明
在生成日报后，自动扫描日报内容，在提及关注标的的段落后添加 `[*关注标的]` 标记。

### 配置方式
编辑 `config/watchlist.json`：
```json
{
  "version": "1.0",
  "last_updated": "2026-08-22",
  "watchlist": [
    {
      "symbol": "600519.SH",
      "name": "贵州茅台",
      "category": "消费"
    }
  ]
}
```

### 标注规则
- 匹配标的名称或股票代码
- 只标注非表格、非标题的正文段落
- 每段只标注一次
- 标记格式：`[*关注标的]`

### 示例效果
```markdown
贵州茅台今日表现良好，创出新高。 [*关注标的]
```

## 功能 8: 假设到期预警

### 实现位置
- `pipeline/hypothesis_workflow.py`: `check_expiring_hypotheses()` 函数
- 在 `prepare_hypothesis_context()` 中自动调用

### 功能说明
每次运行 `prepare` 命令时，自动扫描未来 1-3 天到期的假设，在终端输出醒目提示。

### 使用方式
```bash
python -m pipeline.cli prepare --date 2026-08-22
```

### 输出示例
```
======================================================================
[!] 假设到期预警
======================================================================

[!] H-20260820-001 将于明天到期：市场将突破关键位置
    标的：A_SHARE
    到期日：2026-08-23
    建议今天收盘前检查证据

[!] H-20260820-002 将于3天后到期：板块轮动将持续
    标的：科创50
    到期日：2026-08-25
    建议今天收盘前检查证据

======================================================================
```

### 预警规则
- 检查距离到期日 1-3 天的活跃假设
- 按到期日从近到远排序
- 提供假设 ID、标题、标的、到期日信息

## 已知限制

1. **Windows 终端编码问题**
   - 中文字符在某些 Windows 终端中可能显示为乱码
   - 实际文件内容是正确的 UTF-8 编码
   - 建议使用支持 UTF-8 的终端（如 Windows Terminal）

2. **功能 3 的 LLM 依赖**
   - 需要配置有效的 LLM API
   - fallback 模式下不会生成首稿
   - 首稿质量取决于日报质量

3. **功能 4 的匹配精度**
   - 简单文本匹配，可能误匹配同名词
   - 不处理表格内的标的（避免破坏表格格式）
   - 每段只标注第一个匹配项
